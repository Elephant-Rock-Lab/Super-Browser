# Migration Guide: v1.8 → v1.9

This guide covers breaking changes and deprecations introduced in Super Browser v1.9.

## Backend Selection

**v1.8:** Only Patchright supported. Browser backend was implicit.

**v1.9:** Four backends available. Selection is explicit via `Config`:

```python
from super_browser import SuperBrowser
from super_browser.config import Config
from super_browser.browser.config import SessionConfig

# Auto-detect (recommended, defaults to Patchright)
browser = SuperBrowser()

# Explicit backend via composition root
browser = SuperBrowser(Config(browser=SessionConfig(backend="playwright")))

# Remote CDP endpoint (Docker, Browserless, etc.)
browser = SuperBrowser(Config(browser=SessionConfig(
    backend="cdp",
    endpoint="ws://chromium:9222",
)))
```

Backend options: `"auto"`, `"patchright"`, `"playwright"`, `"selenium"`, `"cdp"`.

## raw_page → engine_page

**v1.8:** Direct access to Playwright `Page` objects via `_page` or `raw_page`.

**v1.9:** All page access goes through `EnginePage` protocol. `raw_page` is deprecated.

```python
# v1.8 (deprecated)
page = sb._page
await page.click("#button")

# v1.9 (recommended)
engine_page = await sb._session.engine.new_page()
await engine_page.click("#button")
```

The facade's public methods (`click`, `fill`, `navigate`, etc.) already use `EnginePage` internally. You only need to change code that accessed `_page` or `_raw_page` directly.

**Deprecation timeline:** `raw_page` emits `DeprecationWarning` in v1.9.x. Removed in v2.0.0.

## CDPBridge → StealthBridge

**v1.8:** Stealth internals used `CDPBridge` directly.

**v1.9:** Stealth internals use `StealthBridge` protocol instead. `CDPBridge` still works but is not the recommended path.

```python
# v1.8 (deprecated)
bridge = cdp_bridge
await bridge.evaluate("navigator.webdriver = false")

# v1.9 (recommended)
bridge = engine_page.stealth_bridge  # StealthBridge protocol
if bridge is not None:
    await bridge.cdp_send("Page.addScriptToEvaluateOnNewDocument", {...})
```

`engine_page.stealth_bridge` returns `None` for backends without CDP/BiDi support (e.g., Playwright with WebKit). Always check for `None`.

## Config as Composition Root

**v1.8:** Subsystem configs passed individually.

**v1.9:** `Config` is the composition root. All subsystem configs are nested:

```python
from super_browser.config import Config, AgentConfig
from super_browser.browser.config import SessionConfig
from super_browser.budget.types import BudgetConfig

cfg = Config(
    browser=SessionConfig(backend="patchright", headless=True),
    agent=AgentConfig(llm_provider="anthropic", llm_api_key="..."),
    budget=BudgetConfig(daily_cap_usd=5.0),
)
```

`SuperBrowserConfig` still works as a legacy alias but is not recommended for new code.

## StealthInjector Selection

**v1.9 new:** Stealth injectors are selected automatically based on backend capabilities:

| Backend | Injector | Timing |
|:--------|:---------|:-------|
| Patchright | CDPInjector | Before page load |
| Playwright (Chromium) | CDPInjector | Before page load |
| Playwright (Firefox) | PageScriptInjector | After page load |
| Selenium (Chrome) | CDPInjector | Before page load |
| CDP Direct | CDPInjector | Before page load |

You don't need to select injectors manually unless you're building a custom backend.

## New pip Install Targets

**v1.8:** `pip install super-browser[browser]`

**v1.9:** Backend-specific install targets:

```bash
pip install super-browser[patchright]    # Default, full stealth
pip install super-browser[playwright]    # Standard Playwright
pip install super-browser[selenium]      # Enterprise CI
pip install super-browser[all]           # Everything
```

## Structured Error Categories

**v1.9 new:** `FailureCategory` adds 5 values beyond `ErrorCategory`:

| New Category | Meaning |
|:-------------|:--------|
| `STALE_REF` | Element reference expired |
| `ELEMENT_OBSCURED` | Element covered by overlay |
| `FRAME_DETACHED` | iframe removed during action |
| `AUTH_REQUIRED` | Login/CAPTCHA wall |
| `RATE_LIMITED` | HTTP 429 or equivalent |

Each failure carries `next_actions` with pre-validated recovery hints. See `docs/error-catalog.md` for the full catalog.

## Quick Checklist

- [ ] Replace `_page` / `raw_page` access with facade methods or `engine_page`
- [ ] Replace direct `CDPBridge` usage with `StealthBridge`
- [ ] Use `Config` instead of `SuperBrowserConfig` for new code
- [ ] Update `pip install` to use backend-specific targets
- [ ] Add `None` checks for `stealth_bridge` on non-CDP backends
- [ ] Handle new `FailureCategory` values in error paths
