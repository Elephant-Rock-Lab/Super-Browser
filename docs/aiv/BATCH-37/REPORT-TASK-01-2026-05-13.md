## Implementation Detail

### 1. `WebRTCEjector` (`webrtc.py`)

Follows the identical class pattern established by `CanvasEjector` and `AudioEjector`:

- **`__slots__`** for `_inject_order` (memory-efficiency, consistency)
- **`_seed_to_js_number()`** — SHA-256 derived deterministic JS PRNG seed
- **`_build_js_payload()`** — generates the IIFE JavaScript string
- **`generate(config)`** — returns `EjectorResult(ejector_id="webrtc", ...)`
- **`inject_order = 30`** — runs after canvas (10) and audio (20)

**JavaScript payload neutralises:**

| Target | Action |
|--------|--------|
| `window.RTCPeerConnection` | Set to `undefined` |
| `window.webkitRTCPeerConnection` | Set to `undefined` |
| `window.mozRTCPeerConnection` | Set to `undefined` |
| `navigator.mediaDevices.enumerateDevices` | Replaced with seeded mock returning 3 device entries |

### 2. Config Extension (`config.py`)

Two new fields added to the frozen `EjectorConfig` dataclass:

```python
webrtc_enabled: bool = True
timing_enabled: bool = True
```

Both default to `True` — opt-out model. `timing_enabled` is reserved for a future BATCH.

### 3. Registry Update (`registry.py`)

- Imported `WebRTCEjector`
- Added conditional block: `if config.webrtc_enabled: results.append(WebRTCEjector().generate(config))`
- Existing sort-by-`inject_order` covers the new ejector naturally

### 4. Pre-existing Test Fix

`test_audio.py::TestRegistryIntegration::test_both_enabled_returns_two_results` was updated to `test_both_enabled_returns_at_least_two_results` with `assert len(results) >= 2` — because `webrtc_enabled` defaults to `True`, the registry now returns 3 results by default.
