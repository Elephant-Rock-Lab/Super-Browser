### 1. Harness — `src/super_browser/stealth/validation/harness.py`

| Component | Description |
|-----------|-------------|

| `StealthRegressionHarness` | Core class with 4 public methods |
| `_matrix_hash()` | SHA-256 over key fingerprint surface fields |

**API surface:**

```
StealthRegressionHarness(baseline_dir=None)
├── capture_baseline(profile, seed, matrix, report) → BaselineResult
├── load_baseline(profile_id) → BaselineResult
├── detect_regression(current_report, baseline) → Sequence[CheckResult]
└── run_ci(profile, seed) → int  (0=pass, 1=regression)
```

- Default baseline directory: `~/.config/super-browser/baselines/`
- File format: `{profile_id}.json`
- Regression = check was **pass** in baseline, now **fail** (not the reverse)

## Architecture Notes

- `BaselineResult` is a **frozen dataclass** matching `CheckResult`/`ValidationReport` pattern from TASK-01
- `matrix_hash` uses SHA-256 over 10 key surface fields (UA, cores, memory, WebGL vendor/renderer, DPR, timezone, locale, webdriver, fonts) — sufficient to detect matrix derivation changes
- CLI uses `importlib`-style lazy imports inside `_stealth_validate()`, consistent with the existing `_stealth_check()` pattern
- Tests use `importlib.util.spec_from_file_location` to load `cli.py` directly, working around the `cli/` package namespace shadowing
