## Deliverables

### 1. NEW: `src/super_browser/security/action_redaction.py`

ActionResult redaction pipeline wiring `SecretRedactor` into result serialization.

**Public API:**

| Function | Purpose |
|---|---|
| `configure_redaction(config)` | Initialize module-level `SecretRedactor` singleton |
| `is_redaction_configured()` | Check if redactor is active |
| `redact_args(args)` | Two-pass argument dict sanitization |
| `redact_context(url)` | URL query-param scrub (standalone, no `SecretRedactor` dependency) |
| `redact_result_dict(d)` | Redact an `ActionResult.to_dict()` output |

**Design decisions:**
- **Module-level singleton** (`_default_redactor`) — zero overhead when not configured (backward compatible)
- **Two-pass `redact_args`**: Pass 1 = key-name matching against `_SENSITIVE_KEYS` frozenset (25 keys); Pass 2 = value-pattern matching via `SecretRedactor` (if configured)
- **`redact_context`** is fully standalone — uses `urllib.parse` only, does NOT delegate to `SecretRedactor`
- **`urlencode(safe="[]:")`** preserves bracket/colon characters in `[REDACTED:query_param]` placeholder

## Implementation Notes

**`urlencode` bracket encoding fix:** `urlencode()` percent-encodes `[`, `]`, and `:` by default. Added `safe="[]:"` parameter to preserve the `[REDACTED:query_param]` placeholder in reconstructed URLs.

**Test isolation for TEST-41-02-07:** The `_default_redactor` module variable is explicitly reset to `None` via `_reset_redactor()` helper before the "no redaction" test to ensure no state leaks from TEST-41-02-06.
